# Schema for slide_plan.json

```json
{
  "paper": "path/to/paper.pdf",
  "reference": "path/to/reference.pptx or folder of images",
  "slides": [
    {
      "purpose": "One-line claim this slide makes",
      "focus": "Optional: Why this is a standalone page — what cognitive problem it solves, what context it needs, what it sets up",
      "composition": {
        "layout": "Brief description of overall arrangement (e.g., 'three cards in horizontal row', 'left diagram + right bullets', 'vertical flow with arrows')",
        "components": [
          {"type": "card", "position": "left third", "content": "Module A overview"},
          {"type": "icon", "position": "above left card", "icon": "gear"},
          {"type": "arrow", "position": "between cards", "direction": "right"}
        ],
        "reasoning": "Why this composition clarifies the content — must be based on content relationship (parallel/comparison/sequence), not 'reference did it'"
      },
      "source": "paper.pdf p. 4, Fig. 2",
      "reference_slide": "ref-07 or page id: which reference page's composition is closest (for style reference, not template)",
      "adaptation": "What is kept from the reference (component styles), what changes for this content (arrangement, connections)",
      "visual": "What illustration/chart/table this page needs; which parts are SVG and which are native shapes/text. If none, state why (e.g., 'text-only definitions list by design')"
    }
  ]
}
```

# Schema for design_brief.md

Must be at least 400 chars and include:

- Title position/size/color and any numbering scheme, citing reference page ids
- Header/footer/logo: reuse the master or not, and why
- Content grid and margins; body size and density (lines per page, columns)
- Emphasis device: color keywords, bold, tags
- **Icons and illustrations style:** linear (stroked outlines), flat/solid, or full-color; line weight; whether icons sit on circular/rounded backgrounds; how the palette is used in artwork; treatment of photos/screenshots
- Diagram, picture and chart treatment
- Palette roles mapped to deckkit roles (navy, blue, rose, pale, zone, line, text)

# Schema for review/review.json

Generated by `render_review.py render`, edited by the agent, checked by `render_review.py check`.

```json
{
  "deck_sha256": "...",
  "slides": [
    {
      "slide": 1,
      "image": "slide-01.png",
      "image_sha256": "...",
      "reviewed": true,
      "assessment": "Specific observation of what you saw: hierarchy, icon style, illustration clarity, text harmony",
      "issues": [],
      "auto_issues": ["clipped: Title (left 50, overlaps 8)", "..."],
      "waivers": {
        "density 0.12 vs 0.34 avg": "Cover page by design"
      }
    }
  ]
}
```

Each slide entry requires:
- `reviewed: true`
- A specific `assessment` (at least 20 chars) noting whether illustrations clarify content and harmonize with text
- If the page has no illustration/chart/table/picture, the assessment must explain why (e.g., "text-only definitions list by design")
- Each item in `auto_issues` fixed (it disappears on rebuild) or waived in `waivers` with a concrete reason
